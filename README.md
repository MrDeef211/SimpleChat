# Примерный очерк работы

## Паттерны

Стараемся использовать [Solid](https://metanit.com/sharp/patterns/5.1.php)

**Обязательно** используем "инъекцию зависимостей"

**Минимальный** уровень абстракции и требований которые мы применяем к архитиктуре как на САПР у Калентьева

## Архитектура

### Проекты

- **Abstractions** - Общие для решения интерфейсы, объекты, команды, DTO
- **Connector** - реализация доставщика сообщений
- **Gui** - интерфейс (пока консоль)
- **SimpleChat** - основное приложение

### Структура

**Gui** подключает **SimpleChat** используя его методы, события и команды для подключения к интерфейсу

**SimpleChat** подключает **Connector** и **Abstraction** и использует их для доставки сообщений

**SimpleChat** не должен зависеть от конкретной реализации **Gui** и **Connector**, но может зависеть от **Abstraction**

`IConnector` - прослойка между **Connector** и **SimpleChat**, все обращения к Connector должны проходить через него.
При необходимости интерфейс можно разделить на несколько (если отдельные его части будут использоваться порознь).
Если нужно дополнить, то либо создаём новый интерфейс, либо наследуем от этого.

`MessageService` и соответственно `IMessageService` внутренние компоненты **SimpleChat** который будет непосредственно подключаться к `IConnector`,
он реализует простую логику, работу с сырыми сообщениями, хранение получателей и базовую валидацию. `IConnector` логику и валидацию не реализует ***вообще***, а только предоставляет методы для работы с сетью.

Для работы непосредственно с **Gui** используются `MessageFactory` и `MessageHandler`.
`MessageFactory` формирует сообщения для `MessageService` и в отличие от последнего непосредственно занимается большей частью валидации и всей логики связанной непосредственно с передачей сообщений.
`MessageHandler` ответственен за принятие и в первую очередь обработку принятых из `MessageService` сообщений. Он содержит событие `MessageArrived` делегат которого передаёт **Gui**.

`IConnector` будет использовать 2 параметра: **DTO** со всеми данными сообщения и некий свой **id** получателей.

`MessageService` также будет использовать **DTO** но **id** будет принимать внутренний из приложения и трансформировать в понятный для `IConnector`.

`MessageFactory` и `MessageHandler` будут запаковывать **string** в **DTO**  и распаковывать **DTO** в **string** и остальные данные соответственно  

**DTO** будет содержать как минимум сообщение, отправителя и время отправки, дальше посмотрим
